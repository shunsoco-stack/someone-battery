# 設計メモ — 誰かの充電

## 目的と公開状態

匿名で自己申告された0〜100%を眺め、「どこかの誰か」を少し想像するアプリ。本人の特定、位置の推定、端末からの自動取得は目的に含めない。

公開版はFirebase未設定のデモモード。新規Firebaseプロジェクト作成上限のため、実運用バックエンドは未接続。実データ用のコードとルールは備えるが、デモの動作を本番Firebaseの稼働実績としない。

## データの境界

```text
ブラウザー
├─ 手動入力 → 入力検証 → Firebase匿名認証 → Security Rules → batteryPosts
├─ Firestoreの有効投稿 → ランダム選択 → 残量・匿名名・相対時刻
├─ 最近見た履歴 → localStorage（実データ／デモで別領域）
├─ Firebase未設定時のみ → 明示デモ（サンプル＋このブラウザーの試用投稿）
└─ 許可された操作名＋mode → /api/analytics
                            └─ 訪問者ヘッダーを固定化 → Vercel Analytics
```

図の実データ経路は、Firebase設定完了時にだけ有効になる。デモ側からFirestoreへ投稿しない。認証失敗や通信エラーを理由に、実データ経路からデモ経路へ移らない。

## 投稿スキーマ

`batteryPosts/{randomDocumentId}`に4フィールドだけを保存する。

| フィールド | 検証と生成 |
| --- | --- |
| `percentage` | 整数、0以上100以下。空・非数・小数・範囲外を拒否。 |
| `createdAt` | `serverTimestamp()`。Rulesで`request.time`と一致させる。 |
| `expiresAt` | クライアントの現在時刻＋24時間。Rulesは`request.time + 24h`の±5分以内を要求。 |
| `anonymousName` | 許可済みの修飾語と動物名から生成。自由入力・地域名・個人属性を入れない。 |

ドキュメントIDにもAuth UIDを使わない。投稿内にUID、IP、位置、端末識別子、メール、自由記述を入れない。呼び名は識別子ではなく、同じ名前の投稿が存在してよい。

Firebase Authentication自体は匿名アカウントを管理する。ブラウザー側はメモリー内の認証状態を利用し、永続的なプロフィールをアプリで保存しない。匿名認証はスパム対策の完全な代替ではない。

## 24時間の扱い

表示可能な投稿は、正常なデータで、作成時刻が未来でなく、現在時刻が`min(createdAt + 24h, expiresAt)`より前のものだけ。読み込み時、表示更新時、履歴復元時に期限を評価する。

Firestore TTLは保存領域の後片付けを担当する。表示期限の保証には使わない。TTLの処理待ちでDBに残っていても、UIは表示しない。期限フィールドの書き込み許容±5分は「表示を24時間5分まで延長する」ためではない。

時計ずれの影響は残る。日付の自動設定が無効な端末では投稿や期限表示が正常に動かない場合がある。より厳密な時刻やサンプリングが必要なら、信頼されたサーバーAPIで処理する設計へ変更する。

Rulesは1ページ200件以下の読み取りを要求するが、期限が過ぎたドキュメントの直接読み取りを一律に拒否する設計ではない。UIで非表示でも、TTL削除までは匿名認証済みクライアントから読める可能性がある。機密情報を保存しない前提と、UI上の期限／物理削除／認可上の期限を明確に区別する。

## ランダム選択

有効な期間の投稿を200件ずつページングし、全候補に対するreservoir samplingで1件選ぶ。最新200件だけをランダム化する実装にはしない。対象が0件なら「まだ誰も投稿していません」。

これは候補全件を読み取るため、表示1回のコストは有効投稿数に比例する。数万件規模へ拡張する際は、信頼されたバックエンドでのバケット化やサンプリングを別途設計する。現在の実装を大規模利用向けの安価なランダムAPIと称さない。

ページング中の新着投稿を含む、全件の厳密な同時点スナップショットは保証しない。要求するのは、取得した有効候補から偏りなく選ぶこと。

## エラーとモード

| 状態 | ユーザーに伝えること |
| --- | --- |
| Firebase設定が全て空 | デモモード。サンプルは実投稿ではなく、試用投稿もこのブラウザーだけ。 |
| Firebase設定が一部不足 | 設定不備。閲覧・送信できない。 |
| 実データの候補なし | まだ誰も投稿していません。 |
| 通信／認証／権限エラー | 処理に失敗したことと再試行。サンプルへは置き換えない。 |
| ローカル保存不可 | その場の閲覧・投稿は継続できるが、履歴の永続保存はできない。クラウド投稿の成功／失敗と分ける。 |
| 投稿完了 | 実送信済みか、ブラウザー内のデモ投稿かを明記。 |

独自の永続的なオフライン投稿キューを設けず、サーバー確認前に投稿完了にしない。Firebase SDK自体のメモリー内で送信が接続回復を待つ可能性はある。共有のキャンセルを成功イベントに数えない。連続操作や遅れて返るレスポンスで、前の結果が現在の画面を上書きしないようにする。

## 端末内の保存

| キー | 内容 |
| --- | --- |
| `someone-battery:history:live:v1` | 実データの最近見た最大12件。期限切れを除外。 |
| `someone-battery:history:demo:v1` | デモの最近見た最大12件。実データと混在させない。 |
| `someone-battery:demo-posts:v1` | このブラウザーで試したデモ投稿、最大50件。 |

保存データは信頼しない。復元時に型、範囲、日時を再検証する。改ざんしたローカルデータをFirestoreへ昇格させない。ブラウザーをまたぐ同期、ユーザーIDによる紐付け、クラウドバックアップは実装しない。

## 計測の設計

訪問者の識別よりも、操作がどれだけ使われたかを優先する。ブラウザー用のVercel Analyticsスクリプトは使わない。

`page_view`、`battery_view`、`battery_post`、`battery_share`の4種と、`mode: demo | live`だけを中継APIで許可する。名前・残量・投稿IDなどの任意データを受け取らない。新規の許可リスト方式で計測用ヘッダーを構築し、実際のUser-Agent、IP、Cookie、参照元、URLクエリーを計測先へ引き継がない。

Vercel側のEvents件数を確認するための実装であり、標準Page Views、ユニーク訪問者数、地域別・端末別指標に意味を持たせない。カスタムイベントには対応する有料プランが必要。送信コードの存在だけでダッシュボードへの収集確認済みとはしない。

DNT／GPC、ユーザーの無効化設定を尊重する。計測に失敗しても閲覧・投稿・共有の主機能を失敗扱いにしない。ただし集計できない状態を検証報告から隠さない。

## UI / アクセシビリティ

- 電池の面積・数値・テキストの3つで残量を示す。色だけで状態を判断させない。
- 通常、低残量、100%の違いを穏やかな動きとコピーで表現する。
- 大きな対象を長時間動かし続けない。`prefers-reduced-motion`では静的表示や短いフェードにする。
- スライダーにラベルを付け、数値入力でも操作可能にする。
- ボタン・ダイアログのキーボード操作、フォーカス移動／復帰、Escで閉じる操作に対応する。
- 読み込み、送信中、完了、空、失敗を別の状態として扱う。
- 履歴削除・計測無効化など、自分の端末に関する選択を提供する。

## PWAの責務

manifestと端末別アイコンを提供する。オフラインでは明示的な案内を表示する。Firestoreの応答や送信結果をサービスワーカーのキャッシュへ保存せず、古い投稿や未送信データを最新の実投稿として見せない。

## 検証境界

1. 純粋関数のテスト: 数値、名前、期限、ランダム選択、履歴、モード分岐。
2. Firestore Emulator: 認証条件、許可スキーマ、拒否ケース、編集／削除拒否。
3. ブラウザー: デモの明示、閲覧、投稿、完了、共有、履歴、キーボード、幅の変化。
4. 公開URL: HTTPS、メタデータ、PWA資産、計測中継、実際の画面撮影。
5. 実Firebase接続: プロジェクト設定後、別ブラウザー間で投稿を共有する実運用スモークテスト。

5はデモモードやエミュレーターでは代替できない。現在の公開版は未接続であることをREADMEと掲載文にも明記する。
